# RyogaのBlog画像

記事の空気を伝える表紙と、本文の感覚や場面を助ける画像を作る。本文の意味を先に捉え、同じ記事の画像同士で線・余白・温度をそろえる。

## 参考とする見た目

[references/style-evidence.md](references/style-evidence.md) に4記事の画像の観察と元画像リンクを記録している。初回の作成時や見た目を合わせる時に読む。実物を再確認できない場合は記録した観察に基づくことを明示し、確認したと装わない。

- 表紙4枚は、横長約1.91:1の写真表現。画像を端まで使い、タイトル文字・ロゴ・装飾枠の後載せがない。コーヒーの接写、空、旅の風景のような一つの主題を選ぶ。
- 最新2本の本文挿絵は、白〜ごく淡い紙地、黒い手描き風の細い輪郭線、少し揺れる線、広い余白。簡略化した人物1人、控えめな表情、象徴的な小物が1〜2点。髪や服の大きな黒塗りや強い影は使わない。
- 体験記事では、会場・街・料理などの実写真も使われる。写真の記録性と線画の比喩を使い分ける。
- IJCNN記事には淡い橙・青のカラー挿絵や文字入りの分割画像もある。題材や明示された希望に合う時の別モードにし、最新線画の規則へ混ぜない。

## 記事から画像へ

1. 本文と画像の役割を確認する。表紙なら記事の空気、本文なら一つの具体例・場面・感覚を選ぶ。関係・比較・時系列・数値が主役なら `$ryoga-blog-diagrams` へ渡す。
2. 実体験を記録する場面には、本人が提供・指定した実写真を優先する。写真がない時は、素材を尋ねるか、イメージ表紙・線画の範囲で進める。過去記事に登場した写真を、新しい体験の記録として使い回さない。
3. [references/prompt-recipes.md](references/prompt-recipes.md) の該当レシピを記事の内容へ書き換え、被写体・構図・余白・比率を具体化する。例の時計・芽・霧を毎回使わない。
4. ラスター画像の生成・編集には、その環境で利用できる画像生成ツールを使う。`imagegen` skillも利用できる場合は先に読む。既存画像を編集する時は先に実物を確認し、参照画像をツールへ渡す。生成を頼まれている場合は画像を作って確認する。画像生成ツールを利用できない時は、制約を明示し、被写体・構図・比率・挿入位置の仕様を渡す。生成していない画像を完成扱いにせず、本文の作業は続ける。個人Macの設定やAPIキーの追加を利用の前提にしない。
プロンプトや仕様だけを依頼された場合は、その成果物で完了し、画像の生成・編集は実行しない。

5. 表紙は約1.91:1、線画は3:2を初期値にする。原画像の被写体を切らず、依頼や掲載先の寸法に合わせる。元画像の実寸と同一の生成サイズを必須にしない。

## 由来とキャプション

生成した写真表現や人物を、本人・実際の旅先・会場を撮影した証拠として説明しない。必要に応じて「イメージ」と分かるキャプションを添える。本人の容姿は、提供された参照と依頼がある場合に合わせる。

他の記事に商品写真やロゴが載っていることは、新しい記事への素材使用許諾を意味しない。本人の素材、使用条件を確認できる素材、生成画像から用途に合うものを選ぶ。撮影者・制作ソフト・生成モデル・フォント名は外観から推測しない。

画像を生成したら、追加の依頼を待たず、画像ごとに短い日本語のキャプション案を1つ添える。場面や感覚を「『目撃』から『実感』へ。」程度の短い一言で表し、本文の説明を繰り返さない。本文と同じ強さの主張にする。「文字なし」の指定は画像内の文字への指定とし、キャプションは画像の外にテキストで渡す。ユーザーがキャプション不要と指定した場合は省く。画像枚数や各節への挿入は固定しない。

## 出力と確認

- 手、顔、本、注ぎ口などの破綻、意図しない文字やロゴ、過剰な小物がないか実画像を確認する。
- 同じ記事の線画で、顔の省略度・線幅・余白・背景の質感がそろっているか確認する。
- 表紙を小さな一覧相当で、本文画像をスマホ相当で見て、主題が分かるか確認する。
- 画像ファイルまたは生成結果、挿入位置、短いキャプション、実写真・外部素材・生成物の別を渡す。

既存noteをRyoga.ioへ紹介する場合の `image` は、その記事で確認できた見出し画像を使う。小さなカード用の `width=240` は配信URLの設定であり、新規表紙の制作解像度ではない。サイトの追加作業は作業先のAGENTS.mdに従う。
