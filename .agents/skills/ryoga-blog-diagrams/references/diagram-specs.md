# 制作仕様と型

以下は実例から導いた制作上の推奨。本文の主張と掲載先の条件に応じて調整する。

## 共通仕様

- キャンバス：基本は1920×1280または2640×1760、白背景。横フローでは必要に応じて横長にする。
- 文字：実行環境で日本語を表示できるサンセリフ。Linux・クラウドでは `Noto Sans CJK JP` / `Noto Sans JP`、macOSでは `Hiragino Kaku Gothic ProN` など、実際に導入済みの日本語フォントを確認して使う。SVGの `font-family` にmacOS専用フォントだけを指定しない。図そのものに必要なラベルを大きく簡潔に置き、PNGへの書き出し後に日本語が保持されることを確認する。
- 配色の実装候補：青 `#1f77b4`、橙 `#ff7f0e`、3系列目が必要な時の緑 `#2ca02c`、本文 `#111111`、補助線は薄いグレー。これは外観に近い候補であり、原画像から採取した色値ではない。
- 構成：図の本体を中心に、十分な白い余白を残す。上部タイトル・副題・下部の説明・定型的な注記は自動で追加しない。本文にある説明を図の周囲へ繰り返さない。
- ラベル：色に加え、線種・直接ラベル・位置で対象を識別する。本文と同じ語を使い、図だけ別の概念名を導入しない。
- レンダリング：構造のある図はSVG、科学的なデータ図は標準的なプロットツールを候補にする。編集可能なソースを残し、PNGを書き出して小さな表示でも読む。

## 比較フロー

入力する内容：

```yaml
主張: 本文で比較したい関係を1文で書く
対象:
  - 名前: 対象A
    段階: [起点, 行動, その後]
  - 名前: 対象B
    段階: [起点, 行動, 残るもの, 可能性]
前提: 必要な条件を1文で書く
```

白い箱と細い黒〜灰の枠、黒い右向き矢印。比較する段階の意味が同じなら列をそろえる。段階数が違う場合は、それぞれの意味を優先する。「可能性」は確定的な結果に見えないラベルにする。

## 本人の経過タイムライン

入力する内容：

```yaml
主張: 何を変えた後の、誰の経過か
節目:
  - 時期: 本人が確認した時点
    状態: その時の体感や事実
    補足: 必要な短い説明
時間の配置: 実時間に比例する / 読みやすい概略配置
根拠: 本人の記録やメモ
```

青い水平線と丸い節目。上に時期、下に状態と説明。未知の日数や節目は作らない。体感なら「本人の記録」と示す。配置が実時間に比例していない時は概略配置と分かるようにする。

## 定性的な比較グラフ

入力する内容：

```yaml
主張: どの関係を理解してほしいか
横軸: 時間や段階など
縦軸: 得られるものの広がりなど
系列:
  - 名前: 対象A
    関係: 本文が説明している変化
  - 名前: 対象B
    関係: 本文が説明している変化
根拠の種別: 概念
前提: 曲線や位置は実測値を示さない
```

左と下の軸、青・橙の線、重ならない凡例。数字がなければ数値目盛りを作らない。青を常に「よい」、橙を常に「悪い」といった固定の意味にしない。成長の話なら、本文に応じて伸びない可能性も緑破線などで整理する。根拠のない倍率や交点の時期を注記しない。

実測データがある場合はこの概念用テンプレートに当てはめず、データ・単位・出典を使う図へ切り替える。

## 二つの観点の位置づけ

二つの軸の意味と、対象ごとの定性的な位置を確認する。四象限は薄い中央線、少数の点、対象名と短い説明で示す。「少なめ／多め」などの言葉を使い、位置に数値的な意味がないことを示す。対象・働き方・生活条件など、比較が成立する範囲を必要な分だけ添える。

## 集合の重なり

注目する共通部分だけを色で強調する。強調した部分から引出線・矢印を伸ばし、要点は円と重ならない白い余白に直接置く。中心へ白い箱や大きな文字を載せて重なりを隠さない。各領域のラベルと引出線が干渉しない配置を選ぶ。

## 研究の段階変化

2〜3パネルで、入力・中間状態・結果の違いを示す。同じ対象はパネル間で位置を維持し、データ点と代表点は別の記号で区別する。比較するパネルの縮尺をそろえる。模式図に研究の性能値や実際の分布を作り足さない。模式図であることの説明が必要なら本文で伝える。本人の論文・スライドに定義があればそちらを優先する。
