# クラウドでBlog・noteを作る

このリポジトリの `.agents/skills/` に、文章・画像・図解の3つのskillと参照資料を置いています。Macの個人用skillフォルダをコピーしたり、写真ライブラリや `.env.local` を渡したりせずに、同じ執筆ルールを利用できます。

## Codex Cloudの初回設定

1. この変更を含むブランチをGitHubの `Ryoga-88/Ryoga` に保存します。既存のクラウド環境を使う場合も、そのブランチを取得できる状態にします。
2. Codexの「Work in → Cloud → Select environment → Create environment」、または「Settings → Codex Cloud → Environments」で `Ryoga-88/Ryoga` を選びます。既存の環境なら「Edit」を開きます。
3. セットアップ会話に下の依頼を貼り、インストール・起動・検証結果を確認して環境を保存・Publish（更新ならRepublish）します。
4. 新しいクラウドタスクでこの環境を選び、この変更を含むブランチで執筆を始めます。環境の保存・公開は、ブログ記事の公開やサイトのデプロイとは別です。

セットアップ用の依頼：

```text
Ryoga-88/Ryogaで日本語のBlog・noteを作る環境を用意してください。
Node.jsは.nvmrcの24.22.1、npmはpackage.jsonの12.2.1を使います。
Install scriptは、リポジトリのルートで npm run cloud:setup を実行してください。
Start skillには、AGENTS.mdとdocs/blog-cloud.mdを読み、プレビューが必要なときに
npm run blog:dev を起動してポート3000の応答を確認する手順を保存してください。
npm run lint と npm run blog:build を実行して結果を報告してください。
.agents/skills/の文章・画像・図解skillと参照資料が読めることも確認してください。
秘密鍵は不要です。PHOTO_CURATION=0を維持してください。
```

パッケージ取得用ネットワークを許可します。noteの取得には `note.com`、見出し画像の表示には記事で確認した画像の配信先へのアクセスが必要です。本文の調査は題材に応じて一次資料の配信先を許可します。取得できない資料は確認済みとせず、未確認事項として残します。

公式案内：[Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environments)、[Build skills](https://learn.chatgpt.com/docs/build-skills)。個人用skillはクラウドへ自動同期されず、リポジトリ内のskillを使います。設定画面の名称・利用できる機能はアカウントによって異なる場合があります。

## 毎回の執筆

たとえば、クラウドタスクに次のように依頼します。体験・考えのメモや既存の草稿も一緒に渡します。

```text
$ryoga-blog-writing を使って、次のメモからnoteの全文草稿を作って。
必要な表紙・線画は $ryoga-blog-images、比較や関係の図は
$ryoga-blog-diagrams を使って。本文と図で未確認の体験・効果は補わないで。
タイトル・目次・中見出し・本文を作り、画像の挿入位置とキャプションも添えて。
成果物は .local/blog/<記事のslug>/ に保存して。

（ここにメモや草稿）
```

画像生成ツールの有無は、そのクラウドタスクで確認します。使える場合は実際の生成物を確認し、使えない場合はファイル名・挿入位置・キャプション・生成プロンプトを渡します。生成APIの秘密鍵を執筆の必須条件にはしません。正確な日本語のラベルを含む図はSVGなどで作り、LinuxではNoto Sans CJK JPなど利用可能な日本語フォントを確認します。

## 草稿と画像の保存

`.local/blog/<slug>/` はGit対象外で、公開サイトにも含まれません。`draft.md`、画像、図のソース、キャプションをまとめます。クラウドの作業領域は永久保存を前提にせず、終了前に成果物をダウンロードするか、使える場合は本人のPageへ保存します。Macにある既存の `.local/blog/` の草稿は自動同期されないため、続きから書くときは必要な原稿・素材だけをそのタスクへ渡します。

Gitで草稿を引き継ぎたいと明示された場合だけ、`drafts/blog/<slug>/draft.md` に本文を保存します。この場所は現在の記事一覧の読み込み対象外ですが、GitHubのリポジトリ閲覧者には見えるため、保存範囲を確認してからコミットします。画像は既存の運用どおりGitへ追加せず、成果物として別に保持します。

記事の公開、コミット・push、PR作成、デプロイは依頼された範囲で実行します。通常の草稿作成だけで `app/contents/blogs/` に原稿を入れないでください。このフォルダのMarkdownはサイトへ掲載されます。

## サイトの表示確認

Node.jsを選択した後、リポジトリのルートで実行します。

```bash
npm run cloud:setup
npm run blog:dev
```

プレビューが利用できる環境では、ポート3000をプレビュー機能で開きます。`blog:dev` はクラウドのプレビューに接続できるよう `0.0.0.0` で待ち受けます。ポートを公開インターネットへ共有せず、環境のプレビュー機能を使ってください。ローカルで使う場合は同じポートの選別サーバーを終了してから起動します。

公開済みnoteを紹介ページへ追加するときは `AGENTS.md` の公開日・正規URL・確認済み見出し画像・重複防止の規則に従います。トップのBlog欄、`/blogs`、紹介ページ、noteへのリンクを確認します。画像の見た目やリンク遷移を確認できない環境では、その確認を未実施として報告します。

```bash
npm run lint
npm run blog:build
```

本番相当の成果物は `.next-preview/` に作ります。起動する場合は次のコマンドを使い、コード変更後は再ビルドします。

```bash
PHOTO_CURATION=0 SITE_PREVIEW=1 npm run start -- --hostname 0.0.0.0 --port 3002
```

本番相当の確認では `/photos/curate`・選別API・`/photos/r2-preview` が404になることも確認します。Macの写真取り込み・高解像度復旧・R2アップロードは、このブログ執筆用環境のセットアップには含みません。noteの取得が失敗しても、保存済みの記事情報と明示した見出し画像でビルドできます。外部画像の実際の表示には配信先への接続が必要です。
